# Что умеет мост

[English](FEATURES.md) · [Українська](FEATURES.uk.md) · **Русский**

Все переключатели — в виджете, кнопка **«Функции…»**. Менять `config.json`
руками не нужно; изменения применяются сразу, без перезапуска.

---

## Режим присутствия — основа всего

Галочка в виджете (или `/away` и `/here` в боте).

| Галочка | Что происходит |
|---|---|
| **стоит** — ты за ПК | всё приходит в Telegram **беззвучно**, ничего не блокируется, опросники остаются в VSCode |
| **снята** — тебя нет | хуки **блокируют** сессию и ждут твоего ответа в Telegram до часа |

Когда ты возвращаешься и ставишь галочку обратно, **все висящие ожидания
немедленно освобождаются** — вопрос возвращается в VSCode, сессия не остаётся
ждать чат, который ты уже не читаешь. Вручную то же самое делает `/release`.

---

## Опросники кнопками

Когда Claude задаёт вопрос с вариантами, он приходит в тему проекта кнопками.
Работает и множественный выбор: отмечаешь несколько, жмёшь «Готово». Можно
ответить и своим текстом — реплаем на сообщение с вопросом.

Только в режиме «не за ПК». За ПК вопрос остаётся в редакторе.

## Постановка задач с телефона

Когда Claude заканчивает ход, в тему приходит сообщение с кнопками
**«▶️ Продолжай»** и **«⏹ Достаточно»**. Любой твой текст в тему становится
следующей задачей — сессия продолжает работу без тебя.

Если ты не ответил за час, сессия просто останавливается. Написанное **позже**
не теряется: Telegram хранит непрочитанное около суток, мост складывает такие
сообщения в очередь и отдаёт их сессии при следующем ходе или запуске.
Посмотреть очередь — `/queue`.

Без `spawn` (ниже) задача может попасть только в существующую сессию — иначе
она ждёт в очереди, пока ты не откроешь проект.

## Запуск агента · `spawn`

**По умолчанию выключено.** Когда задача приходит в тему проекта, а слушать её
некому, мост поднимает сессию сам: `claude -p "<твоя задача>"` в каталоге
проекта.

Запущенный агент — обычная сессия Claude Code, поэтому хуки отчитываются о ней
через этот же мост: живой текст, итог хода, git-сводка. Никакого отдельного
обращения с ней нет.

```json
"spawn": {
  "enabled": false,
  "permission_mode": "acceptEdits",
  "model": null,
  "timeout_seconds": 7200
}
```

- `permission_mode` — один из режимов самого CLI: `acceptEdits`, `auto`,
  `bypassPermissions`, `manual`, `dontAsk`, `plan`. Всё остальное означает, что
  флаг не передаётся вовсе и Claude Code решает сам.
- `model` — `null` оставляет модель, настроенную в CLI.
- `timeout_seconds` — страховка от зависшего агента. В режиме «не за ПК» его
  собственный хук Stop может держать его ещё `wait_seconds` сверх работы,
  поэтому запас нужен большой. `0` — без ограничения.

**Границы, поставленные намеренно:**

- Один агент на проект. Вторая задача, пока работает первый, уходит в очередь.
- Никогда рядом с живой сессией — она получит задачу через свой Stop, так что
  два агента не правят одно дерево одновременно.
- Только для проектов, выбранных из списка. Автообнаруженный проект опознаётся
  по каталогу транскриптов, а это не дерево, в котором можно что-то собрать;
  такие задачи уходят в очередь.
- Если `claude` не найден в `PATH`, в тему приходит сообщение об этом, а не
  тишина.

**Это выполнение кода на твоей машине по сообщению в чате.** Утёкший токен
бота становится правом запустить агента в твоих проектах. Включай осознанно.

## Живой поток текста · `live_messages`

Текст приходит **по мере появления**, а не пачкой в конце хода. Живые блоки
помечены `💬`, в конце хода приходит короткая строка `✅ Проект · 1м 47с`.

Поток идёт **всегда**, в том числе когда ты за ПК — просто беззвучно.

Формат сохраняется: жирный, инлайн-код, блоки кода с подсветкой. Длинные
ответы режутся по границам абзацев и блоков кода, а не посреди строки.
Markdown-таблицы превращаются в моноширинные с выровненными колонками —
своих таблиц в Telegram нет.

## Список задач · `log_when_present.todo`

Todo-лист приходит **одним сообщением, которое редактируется на месте**:
`✅` выполнено (зачёркнуто), `🔸` в работе, `▫️` в очереди, плюс счётчик `2/7`.
Новых сообщений на каждое обновление не плодится.

## Итог хода · `log_when_present.stop`

Строка `✅ Проект · 1м 47с` в конце хода. Если живых блоков по какой-то причине
не ушло (например, демон подняли посреди хода), сюда приходит **полный текст** —
содержимое не теряется никогда.

## Открытие и закрытие сессий · `log_when_present.session`

`🟢 сессия открыта` и `⚪ сессия закрыта`. При закрытии добавляется **git-сводка**
(`git_summary`): ветка и что осталось незакоммиченным. В не-git проектах молчит.

## Падения инструментов · `report_tool_failures`

`❌ Проект · Bash` с командой и текстом ошибки. **По умолчанию выключено** —
в активной работе это шумно. В сводке за день падения считаются в любом случае.

## Остаток лимитов · `usage_report`

После каждого хода — отдельным сообщением в тему **«Лимиты Claude»**:
заполненность 5-часового и недельного окна и **время обнуления**.

```
📊 Лимиты
`████░░░░░░` 43% — 5-часовое окно
   обнуление в 17:34 (через 2ч 15м)
`████████░░` 78% — Недельное
   обнуление 01.08 в 15:20
```

Данные берутся из статус-строки Claude Code (поле `rate_limits`) — никаких
браузерных сессий и учётных данных. Те же цифры видны и внизу окна VSCode.

Если версия Claude Code этого поля не отдаёт, сообщение просто не приходит.
Проценты не выдумываются.

### Когда статус-строка не запускается · `usage_poll`

**По умолчанию включено** — для большинства установок это единственный
источник. Claude Code рисует статус-строку только в своём терминальном
интерфейсе. Если работать через расширение VSCode, кэш не
пишется вообще — метры навсегда остаются на `—`, и учащение опроса файла тут
не помогает ничем.

Он разрешает демону спрашивать тот же эндпоинт, которым пользуется сам CLI (`/api/oauth/usage`), его же OAuth-токеном из
`~/.claude/.credentials.json`:

```json
"usage_poll": {
  "enabled": true,
  "interval_seconds": 60,
  "stale_after_seconds": 45,
  "timeout_seconds": 10
}
```

Статус-строка остаётся основным источником: если кэш записан меньше
`stale_after_seconds` назад, опрос не тратит ни одного запроса. Он только
заполняет тишину.

Это единственное место в мосте, которое трогает учётные данные, поэтому стоит
сказать прямо: токен не уходит никуда, кроме Anthropic, то есть туда же, куда
его отправляет сам CLI, и спрашивает он только твои же лимиты. Не нравится —
выключается в «Функциях». Эндпоинт недокументированный: если он
изменится, опрос начнёт падать, демон напишет об этом дважды и отступит по
экспоненте, а путь через статус-строку продолжит работать.

Заодно оттуда виден **пул Fable**, которого в статус-строке не видели ни разу:
в ответе есть недельное окно с привязкой к модели, и виджет показывает его
отдельной полоской. Сессионный лимит у Fable общий, свой только недельный,
поэтому показывать больше нечего.

## Статус сервисов Anthropic · `status_monitor`

Раз в 5 минут опрашивает `status.claude.com` и пишет в тему **«Статус Claude»**,
когда что-то меняется: общий индикатор, состояние компонента (`Claude API`,
`Claude Code`, …), новый инцидент с текстом или его закрытие. Сбои приходят
**со звуком даже когда ты за ПК** — смысл в том, чтобы не мониторить сайт
руками.

Первый опрос молчит: он только запоминает исходное состояние. Проверить
вручную — `/claude_status`.

## Обрыв хода по ошибке API

Если ход упал из-за ошибки API или лимита, приходит `🛑 сбой API` с текстом.
Обычно узнаёшь раньше, чем это признает статус-страница.

## Сторож зависшего хода · `watchdog`

Если ход идёт дольше 20 минут без завершения — одно уведомление `🐌`. Повторно
по тому же ходу не приходит. Полезно в режиме «не за ПК»: иначе не отличить
работу от зависания.

## Сводка за день · `daily_digest`

В 21:00 таблица по проектам: ходов, ошибок, суммарное время. Счётчики хранятся
`stats_retention_days` дней (по умолчанию 14), более старые дни выбрасываются —
`state.json` не растёт бесконечно.

## Экран Telegram

Меню виджета → **Telegram…**, и он открывается сам, пока мост не настроен.
В нём собрана вся установка:

- токен бота, который проверяется у Telegram **до** сохранения — видно
  `Бот @твойбот на связи` или причину отказа, вместо демона, который молча
  не стартует;
- привязана ли группа и сколько тем создано;
- установлены ли хуки Claude Code, и кнопка, которая их ставит — тот самый
  шаг, ради которого раньше нужен был терминал;
- пять шагов настройки и ссылка, открывающая @BotFather.

Другой токен намеренно сбрасывает привязку: другой бот — другой чат, и
старые номера тем указывают на треды, которых он не видит.

## Обновления · `updates`

**Включено по умолчанию, только для установленной версии.** Демон раз в
несколько часов спрашивает у GitHub последний релиз и ставит его в первый же
момент простоя — когда нет живых сессий, висящих ожиданий и запущенных
агентов. Обновление перезапускает демон, а хук, заблокированный на твоём
вопросе, ушёл бы вместе с ним, унеся ответ, который ты собирался дать.

```json
"updates": { "enabled": true, "interval_hours": 6 }
```

Установщик обновляет поверх: та же установка, хуки на месте, `config.json`
сохраняется. В тему **«Статус Claude»** приходит строка, когда релиз найден,
и вторая — когда он поставлен.

**Он отказывается ставить то, что не смог проверить.** В описании каждого
релиза публикуется SHA-256 установщика; файл, чей хэш не совпал или для
которого хэш не опубликован вовсе, не ставится — только сообщается. Качать
разрешено только с хостов самого GitHub. Пока сборки не подписаны, эта
контрольная сумма — единственное, что стоит за бинарником.

Из исходников не делает ничего: там обновление — это `git pull`. Экран
Telegram в виджете говорит, в каком из двух режимов ты запущен.

## Проекты

Кнопка **«Проекты…»** или команда `/projects`: список проектов, которые Claude
Code уже знает, свежие сверху. Отмеченные получают свою тему в Telegram.

Список — это граница приватности: **не отмеченный проект не отправляет ничего**.

- **Подкаталоги** попадают в тему своего проекта автоматически.
- **Соседние рабочие каталоги** (тестовые данные, клиент игры) привязываются
  к проекту: `python install.py --add-path "C:/путь" --for ИмяПроекта`.
- **`auto_discover`** подключает любой новый проект сам. Удобно, но тогда в
  Telegram пойдёт содержимое всех сессий на машине, включая случайные.
- **`exclude_paths`** — никогда не подключать, даже при `auto_discover`.

## Команды бота

| Команда | Что делает |
|---|---|
| `/help` | список команд |
| `/register` | привязать группу (один раз) |
| `/unregister` | снять привязку и забыть номера тем |
| `/away`, `/here` | режим присутствия |
| `/status` | живые сессии и что ждёт ответа |
| `/projects` | список проектов, нажатие подключает и отключает |
| `/queue` | накопленные задачи |
| `/claude_status` | состояние сервисов Anthropic |
| `/release` | освободить все висящие ожидания |

Привязка намеренно односторонняя. Username бота можно найти, а токен для того,
чтобы ему написать, не нужен, — поэтому второй `/register` из чужого чата увёл
бы туда всё, о чём отчитывается мост. После привязки мост игнорирует
`/register` откуда угодно ещё; перепривязать можно только через `/unregister`
из чата-владельца.

## Границы, о которых стоит знать

- **Ожидание ограничено часом.** Замерено: хук держит сессию полный час, и она
  штатно доигрывает ход. Больше не проверялось.
- **Мост говорит на границах хода.** Внутри длинного хода событий нет, кроме
  живого текста и обновлений todo. Тишина в теме во время долгой работы —
  это норма.
- **Ответ на опросник** передаётся через механизм отклонения вызова, поэтому в
  транскрипте он выглядит как отклонённый инструмент с текстом твоего выбора.
  На работу это не влияет.
- **Задачу в несуществующую сессию** поставить нельзя, пока не включён
  `spawn`, — иначе она ждёт в очереди.
