# Встановлення

[English](INSTALL.md) · **Українська** · [Русский](INSTALL.ru.md)

## Коротко

1. Завантаж **`ClaudeTelegram-Setup.exe`** зі
   [сторінки релізів](https://github.com/bonuxq/claude-telegram-bridge/releases)
   і запусти.
2. Віджет сам відкриє екран налаштування. Пройди п'ять кроків у ньому.

Це все встановлення. Жодного Python, термінала й редагування файлів —
інсталятор несе середовище з собою і сам прописує хуки Claude Code.

Лише Windows. Демон і хуки — звичайний Python і працювали б будь-де, але
віджет побудований на Win32 API, і порту немає.

---

## Що робить інсталятор

- Ставить у `%LOCALAPPDATA%\ClaudeTelegram` — **без прав адміністратора**.
  За межі твого профілю він не пише нічого.
- Прописує хуки і статус-рядок у `~/.claude/settings.json`, лишаючи
  резервну копію з відміткою часу і не чіпаючи твої власні хуки.
- За галочкою — запуск моста під час входу в систему.
- Наприкінці піднімає демон і віджет.

Видалення прибирає хуки і саму програму, але лишає `config.json`:
перевстановлення не має коштувати тобі токена й списку проєктів.

## Екран налаштування

Відкривається сам на свіжому встановленні, потім живе в меню віджета під
пунктом **Telegram…**.

### 1. Створити бота

Натисни **Відкрити @BotFather**, надішли йому `/newbot`, придумай ім'я та
username. У відповідь він видасть токен вигляду `1234567890:AAF...`.

### 2. Вставити токен

У поле, потім **Зберегти й перевірити**. Міст питає в Telegram, чи робочий
токен, ще до збереження, тож результат видно одразу:

- `Бот @твійбот на зв'язку` — готово.
- `Telegram не прийняв цей токен` — він хибний або відкликаний; міст лишить
  старий, а не збереже зламаний.

### 3. Створити групу

**Супергрупу**, не звичайну групу і не канал. У її налаштуваннях увімкни
**Теми** (Topics) — міст дає кожному проєкту свою тему, без них розділяти
нічого.

### 4. Додати бота адміністратором

Без прав адміністратора він не створить теми. Статус адміна заразом дозволяє
йому читати звичайні повідомлення — тому налаштування приватності в
BotFather ролі не грає.

### 5. Прив'язати групу

Надішли в групі `/register`. Бот підтвердить, і теми **«Статус Claude»** та
**«Ліміти Claude»** з'являться самі.

Прив'язка навмисно одностороння: після неї `/register` із будь-якого іншого
чату ігнорується, тож знайти твого бота недостатньо, щоб відвести його
звіти. Щоб перенести міст в іншу групу, спершу надішли `/unregister` у
поточній.

### 6. Хуки

Екран налаштування показує, чи вони на місці, і ставить їх однією кнопкою.
Інсталятор уже це зробив, тож зазвичай там просто написано
`Хуки Claude Code встановлено`.

**Перезапусти вікна VSCode, відкриті під час встановлення** — хуки
підхоплюються при старті вікна.

## Оновлення

Встановлена версія тримає себе в актуальному стані: дивиться релізи на
GitHub і ставить їх, коли міст простоює, — ніколи посеред сесії. Вимикається
у «Функціях» → **«Оновлюватися автоматично»**.

Якщо випускаєш реліз сам: запусти `python build.py`, виклади інсталятор і
встав надрукований ним рядок із контрольною сумою в опис релізу —
оновлення відмовляється ставити те, чого не може перевірити.

## Вибір проєктів

Шляхи вводити не треба. Меню віджета → **«Проєкти…»** або `/projects` у
чаті: з'явиться список проєктів, які Claude Code уже знає, свіжі згори.
Позначені отримують свою тему в Telegram.

Цей список — межа приватності: **непозначений проєкт не надсилає нічого**.

## Запуск із джерел

Якщо бінарник запускати не хочеться:

```bash
git clone https://github.com/bonuxq/claude-telegram-bridge
cd claude-telegram-bridge
cp config.example.json config.json
python install.py                 # хуки і статус-рядок
python -m claudetg.daemon         # демон
python widget.pyw                 # віджет
```

Python 3.9+ і більше нічого — увесь міст на стандартній бібліотеці. Екран
налаштування з джерел працює так само.

Зібрати інсталятор самому:

```bash
pip install pyinstaller
python build.py
```

## Якщо щось не працює

**У Telegram тиша.** Спершу подивись екран налаштування: він каже, чи
прийнято токен, чи прив'язано групу і чи встановлено хуки. Ці три пункти
покривають майже все.

**Хуки не спрацьовують.** Вікно VSCode, відкрите до встановлення, зазвичай
підхоплює їх на льоту, але не завжди. Перезапусти вікно.

**Тема проєкту не з'явилася.** Тема створюється при першій події від сесії.
Усередині довгого ходу подій немає — міст говорить на межах ходу.

**Ліміти порожні.** Claude Code малює статус-рядок лише у своєму
термінальному інтерфейсі, тому під час роботи через VSCode його ніхто не
викликає. Увімкни **«Опитувати ліміти самому»** у «Функціях» — демон почне
запитувати їх напряму раз на 30 секунд. Деталі — у
[FEATURES.uk.md](FEATURES.uk.md#коли-статус-рядок-не-запускається--usage_poll).

**Демон не відповідає.** Дивись `daemon.log` поруч із виконуваним файлом.
Якщо порт 8787 зайнятий — демон уже запущено, другий не потрібен. Віджет
пише свої падіння у `widget.log` там само.

**Windows пише «невідомий видавець».** Збірка поки не підписана. Можна
перевірити джерела і зібрати самому командами вище.

## Безпека

- `config.json` містить токен бота. Витік токена дає сторонньому читати твої
  сповіщення і писати у твою групу.
- Міст надсилає в Telegram вміст роботи: текст відповідей, помилки, списки
  завдань. У чат потрапляє лише те, що стосується **позначених** проєктів.
- `auto_discover` підключає будь-який проєкт автоматично — зручно, але тоді
  назовні піде вміст усіх сесій на машині.
- `spawn` (типово вимкнено) запускає агента за повідомленням із Telegram. Це
  виконання коду на твоїй машині за повідомленням у чаті, тож витік токена
  стає правом запустити агента у твоїх проєктах.
- `usage_poll` (типово вимкнено) — єдине місце, що торкається облікових
  даних: читає OAuth-токен Claude Code, щоб спитати ліміти в Anthropic.
