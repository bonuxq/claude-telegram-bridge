# Claude Code ↔ Telegram bridge

[English](README.md) · [Українська](README.uk.md) · **Русский**

Удалённое управление живыми сессиями Claude Code из Telegram: опросники
приходят кнопками, итог хода — текстом, ответ из чата продолжает работу.
Зависимостей нет, только стандартная библиотека Python.

![Виджет](docs/widget.png)

## Как это устроено

Расширение VSCode не даёт вставить сообщение в идущую сессию, поэтому
подключение идёт через **хуки** — штатный механизм расширения Claude Code.

```
VSCode (сессия) --hook--> hookc.py --HTTP--> claudetg.daemon <--getUpdates--> Telegram
```

Демон нужен потому, что поток обновлений бота может читать **только один**
потребитель: два окна VSCode, опрашивающих один токен, получали бы `409` и
воровали ответы друг у друга.

## Режим присутствия

| Режим | Поведение |
|---|---|
| **За ПК** (по умолчанию) | хуки шлют в чат только то, что разрешено фильтром «За ПК: …» (можно — вообще ничего), и сразу возвращаются. Опросники — в VSCode, как обычно. |
| **Не за ПК** | хуки блокируют сессию и ждут ответа в Telegram. |

Переключение — кнопка виджета, `/away` / `/here` в боте, или автоматически
по бездействию (см. виджет).

## События

| Хук | Что делает |
|---|---|
| `SessionStart` | регистрирует сессию, заводит топик проекта, отдаёт накопленную очередь задач |
| `PreToolUse` (`AskUserQuestion`) | публикует опросник кнопками, ждёт выбор |
| `Stop` | шлёт итог хода (проект · длительность), ждёт следующую задачу |
| `PostToolUse` (`TodoWrite`) | список задач одним сообщением, которое **редактируется на месте** |
| `PostToolUseFailure` | шлёт упавшие команды с текстом ошибки |
| `StopFailure` | ход оборвался ошибкой API или лимитом — сообщает со звуком |
| `UserPromptSubmit` | отмечает начало хода для сторожа зависаний |
| `SessionEnd` | закрывает сессию, добавляет git-сводку |

## Сторож, сводки, git

- **Сторож зависшего хода** — если ход идёт дольше `watchdog.minutes`
  (по умолчанию 20) без завершения, приходит одно уведомление. Повторно по
  тому же ходу не повторяется; сбрасывается на `Stop`.
- **Сводка за день** — в `daily_digest.hour` (по умолчанию 21:00) таблица
  по проектам: ходов, ошибок, суммарное время.
- **Git-сводка** — при закрытии сессии: ветка и что осталось
  незакоммиченным. В не-git проектах молчит. Отключается `git_summary`.

## Живой поток

Текст приходит **по мере появления**, а не пачкой в конце хода: демон читает
хвост транскрипта раз в секунду и отправляет каждый готовый блок. Живые блоки
идут с `💬`, в конце хода — короткая строка `✅ Проект · 1м 47с`.

За ПК поток подчиняется галочке «За ПК: живой поток текста»; в режиме
«не за ПК» идёт всегда. Если живых блоков не ушло (например, демон подняли
посреди хода), финальное сообщение придёт с полным текстом — содержимое не
теряется никогда.

## Виджет на рабочем столе

`widget.pyw` — безрамочная тёмная карточка поверх всех окон (Tkinter + ctypes,
без зависимостей). Перетаскивается за любое место, углы скруглены, прозрачность
настраивается.

- **Капсула-кнопка присутствия**: 🟢 «Я за ПК», 🟡 «Не за ПК», 🔴 «Мост
  offline» (клик поднимет демона). Подсказка режима — в тултипе.
- **Метры лимитов, по секции на вендора**: под заголовком **Claude** —
  5-часовое окно, недельное и собственное недельное окно Fable; под
  **Codex** — его недельное. Обе секции пишут «Неделя» и означают разные
  недели, ради этого заголовки и нужны. Процент и цвет по загрузке
  (спокойный → жёлтый ≥70% → красный ≥90%), время обнуления — в тултипе.
  Клик по заголовку сворачивает секцию, вкладка **Fable** в заголовке
  Claude — только свою строку.
- **Секция есть, только пока есть вендор**: нет `~/.claude` — нет строк
  Claude и вкладки Fable; нет Codex — нет его строки; нет обоих — блок
  исчезает целиком, а не висит пустым.
- **Лимиты Codex** читаются из логов, которые Codex и так пишет
  (`~/.codex/sessions/**/rollout-*.jsonl`, события `token_count`): без сети,
  без токенов, и хвост файла перечитывается, только когда файл вырос. У
  Codex отдаёт по пулу на модель плюс собственный пул тарифа; в строке —
  недельное окно тарифа, найденное по длине окна, а не по тому, в каком поле
  оно приехало: нетронутый модельный пул показывает ноль и пишется в лог так
  же часто. Если окно успело обнулиться, показывается «—», а не выдуманный
  ноль.
- **Тревожный фон**: на ≥90% 5-часового окна карточка становится
  тускло-красной, на ≥90% недельного — красной. Недельное перебивает
  сессионное: сессионное само дольётся, недельное — нет.
- **Меню** (правый клик, шестерёнка или иконка в трее): Проекты, Функции,
  Прозрачность, Масштаб, Клики сквозь виджет, Авто «не за ПК», Сбросить положение
  виджета, Скрыть в трей, Закрыть. Меню и окна «Проекты»/«Функции» — в том
  же тёмном стиле, изменения применяются сразу. Версия сборки — в тултипе
  шестерёнки и в подсказке иконки в трее.
- **Клики сквозь виджет**: карточка перестаёт ловить мышь вовсе и может
  висеть поверх редактора, не мешая. Обратно — только через иконку в трее
  (правый клик → то же меню), потому что кликнуть по самой карточке уже
  нельзя.
- **Сбросить положение виджета**: карточка, оставшаяся на отключённом
  мониторе, возвращается сама — и при запуске, и на ходу. Пункт меню — ручной
  выход: он же возвращает прозрачность и сквозной клик к значениям по
  умолчанию. Доступен из трея, поэтому работает, даже когда по карточке
  нельзя кликнуть или её нигде не видно.
- **Telegram можно выключить целиком**: первая строка экрана «Telegram…» и
  первый тумблер в «Функциях» (`telegram.enabled`). Выключенный мост ничего
  не шлёт и не слушает, режим «не за ПК» схлопывается в «за ПК» (заблокированному
  хуку всё равно некому ответить), а с карточки уходит вся половина про
  присутствие: капсула, строка будильника и пункты меню, которые без чата
  ничего не значат. Остаётся монитор лимитов с шестерёнкой. Токен остаётся
  сохранённым. Свежая установка стартует выключенной; установка, где уже
  есть токен и группа, продолжает работать — отсутствующий переключатель
  означает «включено, если настроено».
- **Масштаб**: от 70% до 120% — разом шрифты, полоски и отступы, чтобы
  карточка помещалась в угол, не занимая этот угол целиком. Tk измеряет
  шрифт при создании виджета, поэтому карточка перезапускает себя, чтобы
  перерисоваться в новом размере — так же, как при смене языка.
- **Трей**: левый клик — скрыть/показать виджет, правый — меню. На иконке —
  процент одного из метров, в его же цвете; какого именно, выбирается в меню
  («В трее показывать»): сессия, неделя, Fable или Codex.
- **Авто «не за ПК»**: после N минут бездействия (клавиатура+мышь всей
  системы) мост сам уходит в away; возвращает его только **нажатие клавиши**
  — задетая мышь не выдернет сессию из Telegram. Ручное переключение
  автоматика никогда не отменяет.

## Остаток лимитов после каждого хода

Отдельным сообщением в фиксированный топик «Лимиты Claude»: заполненность
5-часового и недельного окна плюс **время обнуления**.

Источник данных — не веб-API claude.ai и не браузерная сессия, а
`statusline.py`: Claude Code передаёт статус-строке поле `rate_limits` с
`used_percentage` и `resets_at` для окон `five_hour` и `seven_day`. Хукам
это поле не отдаётся, поэтому статус-строка кэширует его в `usage.json`, а
демон и виджет читают кэш. Никаких учётных данных не требуется.

Статус-строка рисуется только в терминальном интерфейсе Claude Code — при
работе через расширение VSCode кэш не пишется вообще. На этот случай есть
`usage_poll` (по умолчанию выключен): демон раз в 30 секунд сам спрашивает
`/api/oauth/usage` — тот же эндпоинт и тот же токен, которыми пользуется CLI,
— и пишет ответ в тот же `usage.json`. Свежую запись статус-строки он не
трогает. Подробности и оговорки — в [FEATURES.ru.md](FEATURES.ru.md).

Если версия Claude Code это поле не присылает — сообщение просто не
отправляется. Устаревший кэш (старше `usage_report.max_age_seconds`) тоже
игнорируется: лучше промолчать, чем показать цифры, которым нельзя верить.

## Выбор проектов

Пути руками вводить не нужно. Мост сам находит все проекты, о которых знает
Claude Code (каталоги в `~/.claude/projects`), и показывает списком —
свежие сверху, с настоящим корнем и пометкой «нет на диске» для мёртвых:

- **в виджете** — меню → «Проекты…», галочки применяются сразу;
- **в боте** — команда `/projects`, нажатие переключает подключение.

Отмеченный проект получает свой топик. Список — это и есть граница
приватности: **не отмеченный проект не отправляет в Telegram ничего**. Если
хочется, чтобы подхватывался любой новый проект автоматически, есть
`auto_discover: true` — но тогда наружу пойдёт содержимое всех сессий на
машине, включая случайные.

## Несколько рабочих каталогов у одного проекта

Claude часто уходит работать в соседние деревья (тестовые данные, клиент
игры, референсный чекаут). Они должны попадать в топик **своего** проекта:

```bash
python install.py --add-path "C:/Users/Me/Desktop/core" --for ReverseL2
```

## Возврат управления

Если ты снимаешь режим «не за ПК», пока хук ждёт ответа, **все ожидания
немедленно освобождаются** и управление возвращается в VSCode: висящий
опросник снова появится в редакторе, `Stop` просто отдаст ход. Вручную —
`/release`.

## Монитор status.claude.com

Отдельный поток опрашивает статус-страницу Anthropic раз в 5 минут и пишет
в топик «Статус Claude», когда что-то меняется: общий индикатор, состояние
компонента, новый инцидент или его закрытие. Сбои приходят **со звуком даже
в режиме «за ПК»**. Проверить вручную: `/claude_status`.

## Языки

Мост говорит на 9 языках: English, Українська, Русский, 한국어, 中文,
Tiếng Việt, Ελληνικά, Português, Español. Язык определяется по системе
автоматически; переключить — меню виджета → «Язык» или `"language"` в
`config.json`. Переводы — обычные файлы `lang/messages_*.properties`:
новый язык добавляется одним файлом, без кода.

## Установка

Скачай **`ClaudeTelegram-Setup.exe`** со
[страницы релизов](https://github.com/bonuxq/claude-telegram-bridge/releases)
и запусти. Прав администратора не нужно, Python не нужен: установщик несёт
рантайм с собой и сам прописывает хуки Claude Code.

Дальше виджет сам откроет экран настройки: вставить токен бота (он
проверяется у Telegram до сохранения), создать супергруппу с включёнными
**Темами**, добавить бота администратором и отправить в группе `/register`.

Из исходников — тоже можно, нужен только Python 3.9+:

```bash
python install.py                                   # хуки в ~/.claude/settings.json (с бэкапом)
python -m claudetg.daemon                           # демон (или поднимется сам из хука)
python widget.pyw                                   # виджет
```

Подробности и разбор проблем — в [INSTALL.ru.md](INSTALL.ru.md), полный
разбор функций — в [FEATURES.ru.md](FEATURES.ru.md).

## Обновления

Установленная версия обновляется сама: демон раз в несколько часов смотрит
релизы на GitHub и ставит новый в первый же момент простоя — когда нет живых
сессий и висящих ожиданий. Файл, чью контрольную сумму не удалось сверить с
опубликованной, не ставится. Из исходников обновление — это `git pull`.

## Команды бота

`/help` — список команд · `/register` — привязать группу ·
`/unregister` — снять привязку · `/away`, `/here` — режим присутствия ·
`/status` — живые сессии · `/queue` — накопленные задачи ·
`/claude_status` — состояние сервисов Anthropic ·
`/release` — освободить все висящие ожидания

Привязка односторонняя: после неё `/register` из любого другого чата
игнорируется — найти бота недостаточно, чтобы увести его отчёты себе.

## Границы, о которых надо знать

- **Ожидание ограничено часом.** Замерено: хук с `timeout: 3600` держит
  сессию полный час и она штатно доигрывает ход.
- **Ответ позже таймаута не теряется**: Telegram хранит непрочитанные
  апдейты около суток, демон складывает их в очередь и отдаёт сессии при
  следующем `Stop` или `SessionStart`.
- **Ответ на `AskUserQuestion` отдаётся через `deny` +
  `permissionDecisionReason`** — в транскрипте вызов выглядит как
  отклонённый, выбор передаётся текстом.
- **Задача в несуществующую сессию** по умолчанию копится в очереди и
  отдаётся при следующем старте. `spawn.enabled` поднимает под неё
  `claude -p` в каталоге проекта — выключено по умолчанию, потому что это
  выполнение кода на твоей машине по сообщению в чате.
- Хуки глобальные, но `hookc.py` мгновенно выходит в любом проекте, не
  указанном в `projects` конфига.
